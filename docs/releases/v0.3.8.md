# v0.3.8 — private signup receipt and reconciliation dates

**No live Google add proven.** This release follows the 0.3.7 public Group
slug correction. A merge triggers the signed APK release pipeline (ADR 0006).

- Send to Meeple history separates submission receipt, first record receipt,
  actual addition date, and locally recorded membership verification. Unknown
  dates stay Unknown; manual Refresh outcomes retains last-known dates offline.
- The private receiver keeps immutable captured names/sources and receipts,
  membership outcome history, and private JSON export / consistent SQLite backup.
  This is a reconciliation ledger, not a current Google roster.
- Contacts never become mailing-list additions. Receipt is not membership;
  verification dates are operator-attested, not independent Google checks.

Receipt dates require a separately coordinated receiver upgrade; shipping the
APK alone does not upgrade the receiver. Stop old writers and take a private
SQLite backup before that upgrade. The deployed receiver is out of scope for
this change. Receiver activation is separate and owner-gated. The transport
already shipped in v0.3.2 supports runtime-approved HTTPS `*.ts.net` origins; this version adds
the date display, not a new endpoint entitlement. No receiver is activated by
merging this PR. No Google adapter, login automation or enrollment cron is added.
Google authentication and actual membership feedback remain blocked/unproven.

## Delivery checks still required

Owner merge → exact-main CI → signed `v0.3.8` release with
`bgn-coordinator_0.3.8_arm64.apk` → same-signer in-app update on the kept phone.
Do not uninstall or replace it with a debug-signed APK. Confirm local capture,
contacts, notes and transfer history survive; then verify Tailscale on/off,
receipt/retry and manual date refresh against the separately approved receiver.
Local tests/browser checks are not native phone or live Google proof.
